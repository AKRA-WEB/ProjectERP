# Track: Debug — Select Component options.map Crash

**Created:** 2026-05-11
**Status:** Active
**Architect:** Claude

---

## Error

```
> 41 |           {options.map((opt) => (
     |                    ^
TypeError: Cannot read properties of undefined (reading 'map')
```

**File:** `components/ui/Select.tsx` line 41

---

## Root Cause

`Select.tsx` declares `options: SelectOption[]` as a **required prop with no default**.

Gemini-generated pages (Sales, Accounting, POS modules) used `<Select>` as a standard HTML
wrapper — passing JSX `<option>` children instead of the `options` array prop:

```tsx
// ❌ How Gemini wrote it (children pattern — options prop = undefined)
<Select label="ลูกค้า" value={id} onChange={...}>
  <option value="">-- เลือก --</option>
  {customers.map(c => <option key={c.id} value={c.id}>{c.name_th}</option>)}
</Select>

// ✅ How the component expects it (options prop pattern)
<Select label="ลูกค้า" value={id} options={customers.map(c => ({
  value: c.id,
  label: c.name_th,
}))} placeholder="-- เลือก --" />
```

When children are passed but no `options` prop, `options` is `undefined` → crash.

## Fix Strategy

**Fix only `components/ui/Select.tsx`** (1 file). Do NOT rewrite all the caller pages —
the children pattern is valid and readable. Make the component support both patterns.

### Changes to `Select.tsx`

1. Make `options` optional: `options?: SelectOption[]`
2. Destructure `children` from props explicitly
3. Render logic: if `options` is provided → render from options (existing behavior, backward-compatible); else → render children

```typescript
interface SelectProps extends SelectHTMLAttributes<HTMLSelectElement> {
  label?: string;
  error?: string;
  options?: SelectOption[];  // was required, now optional
  placeholder?: string;
}

export const Select = forwardRef<HTMLSelectElement, SelectProps>(
  ({ label, error, options, placeholder, className, id, children, ...props }, ref) => {
    const selectId = id ?? label?.toLowerCase().replace(/\s+/g, '-');
    return (
      <div className="flex flex-col gap-1">
        {label && (
          <label htmlFor={selectId} className="text-sm font-medium text-gray-700">
            {label}
          </label>
        )}
        <select
          ref={ref}
          id={selectId}
          className={cn(
            'rounded-md border px-3 py-2 text-sm shadow-sm focus:outline-none focus:ring-2 focus:ring-blue-500',
            error ? 'border-red-500 focus:ring-red-500' : 'border-gray-300',
            props.disabled && 'cursor-not-allowed bg-gray-50',
            className
          )}
          aria-invalid={!!error}
          {...props}
        >
          {options != null ? (
            <>
              {placeholder && <option value="">{placeholder}</option>}
              {options.map((opt) => (
                <option key={opt.value} value={opt.value} disabled={opt.disabled}>
                  {opt.label}
                </option>
              ))}
            </>
          ) : (
            children
          )}
        </select>
        {error && <p className="text-xs text-red-600">{error}</p>}
      </div>
    );
  }
);
Select.displayName = 'Select';
```

### Why this is safe

- Old pages (WMS) pass `options={[...]}` → `options != null` → renders from options prop. **Zero behavior change.**
- New pages (Sales/Accounting/POS) pass children, no options prop → `options` is `undefined` → `options != null` is `false` → renders `children`. **Crash eliminated.**
- Pages that pass neither → renders nothing. No crash.
- `children` extracted from `...props` so the spread no longer passes it to the native `<select>` (avoids React warning about unknown prop — actually children IS valid in spread for React elements, but explicit destructure is cleaner).
